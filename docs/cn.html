aria

Apple Music 无损音频下载服务 — 提供 AAC 和 Hi-Res ALAC（24-bit / 48 kHz）的 HTTP API 接口。追求速度、稳定和易集成。

ALAC 24-bit AAC 256k REST API

架构

客户端 (aria_lite.py / curl / 任意 HTTP 客户端) │ ├─ GET /download/<id>?fmt=alac │ ▼ aria 服务 (Flask :8899) │ ├─ apple_api.py → Apple Music 目录 API（元数据、HLS URL） ├─ m3u8_select.py → 从 HLS 主播放列表中选择最佳 ALAC 变体 ├─ m4s_parser.py → 解析 fragmented MP4，提取加密 samples │ ├─ DecryptPool（轮询 N 个 sidecar 实例） │ ├─ sidecar :47010 → FairPlay 逐 sample 解密 │ ├─ sidecar :47011 →（实例 2） │ └─ sidecar :47020 → HLS 主播放列表 URL 解析 │ ├─ m4a_writer.py → 将解密数据写回 ALAC m4a │ ├─ 重命名 enca → alac（所有 stsd 条目） │ └─ 清除 senc/saiz/saio → free 空盒 │ └─ 响应: 解密后的 .m4a（含元数据 + 封面）

API 参考

方法端点说明
GET/health服务健康状态 + 各解密实例状态
GET/search?q=关键词&type=songs搜索歌曲、专辑、艺术家（分页）
GET/song/<id>歌曲元数据（标题、艺术家、封面、歌词标志、ISRC）
GET/album/<id>专辑详情 + 分页曲目列表
GET/artist/<id>艺术家详情 + 分页专辑列表
GET/download/<id>下载单曲（默认 AAC；?fmt=alac 获取 Hi-Res）
GET/album/<id>/download整张专辑下载（ZIP）
POST/batch批量下载：{"ids":[...],"fmt":"alac"}

除 / 和 /health 外，所有端点需要 Authorization: Bearer TOKEN。

模块说明

server.py
Flask HTTP API — 路由、认证、下载编排、DecryptPool 集成
apple_api.py
Apple Music REST 客户端 — 目录搜索、歌曲/专辑元数据、token 引导
aria_rpc.py
sidecar TCP 流水线客户端 — 发送加密 samples，接收明文
decryptor.py
ALAC 流水线编排器 — PersistentDecryptSession、DecryptPool、预取
m3u8_select.py
HLS 变体选择器 — 按采样率和位深选择最佳 ALAC 流
m4s_parser.py
Fragmented MP4 解析器 — 提取 samples、trun 偏移、sample descriptions
m4a_writer.py
ALAC m4a 输出 — 修补 stsd（enca→alac），清除加密元数据
aac_decrypt.py
AAC 流水线 — Widevine CDM + mp4decrypt 处理 AAC 256k 层级
aria_sidecar.py
进程管理器 — 启动 N 个 sidecar 实例，健康检查，自动重启

快速开始

# 1. 安装依赖
pip install -r requirements.txt   # flask, httpx, m3u8, pywidevine, mutagen

# 2. 配置 Apple Music 凭据
mkdir -p ~/.config/aria
cat > ~/.config/aria/config.json <<'EOF'
{
  "accessToken": "eyJh...",
  "mediaUserToken": "0.AmW..."
}
EOF

# 3. 启动 sidecar（FairPlay 解密服务）
python3 aria_sidecar.py -F --instances 2

# 4. 启动 aria 服务
export API_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(24))')"
export ARIA_INSTANCES=2
python3 server.py --port 8899

# 5. 使用
curl -H "Authorization: Bearer $API_TOKEN" \
  "http://localhost:8899/download/1615585008?fmt=alac" -o song.m4a

ALAC 解密流水线深入解析

一首 ALAC 歌曲从 Apple CDN 到可播放 .m4a 文件的完整旅程：

1
解析 HLS 主播放列表

sidecar 的 m3u8 端口（47020）将 Apple Music adamId 解析为 enhanced-HLS 主播放列表 URL。m3u8_select.py 选择最高质量的 ALAC 变体（通常为 48 kHz / 24-bit）。

2
下载加密流

选定的变体 URL 指向单个 fragmented MP4 文件（4 分钟歌曲约 50 MB）。m4s_parser.py 将其解析为独立的加密 samples（每首歌通常 2000-3000 个）。

3
FairPlay 解密

aria_rpc.py 通过流水线 TCP 连接（端口 47010）将每个 sample 发送给 sidecar。writer 和 reader 线程并发运行——writer 推送密文，reader 收集明文。单首歌约 4 秒。

4
修补容器格式（m4a_writer）

关键步骤。三个转换将加密的 fragmented MP4 变为有效的 ALAC 文件：

a) 重命名 stsd 中所有 enca sample entry 为 alac（不只是第一个——这是原始 bug）

b) 移除每个 entry 中的 sinf 盒（DRM 元数据）

c) 将每个 traf 中的 senc/saiz/saio 盒覆写为 free（清除加密标志）

5
打标签 & 输出

通过 mutagen 的 MP4 atoms 嵌入元数据（标题、艺术家、专辑、封面）。文件被缓存并作为标准 .m4a 提供下载。
